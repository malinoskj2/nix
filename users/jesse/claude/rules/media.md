# Images and videos

- Save every screenshot, screen recording and other development image or video in `.tmp/` at the root of the current repository or worktree (create it if missing). Resolve that root with `git rev-parse --show-toplevel`; `.tmp/` is globally Git-ignored.
- When showing me three or more images or videos at once, or asking me to look at or choose between media, present them with `media-gallery` (see its skill), with anything that needs my decision under Needs review. I reply in chat by `#id`.
- In an Orca chat, whenever a `media-gallery` batch contains still images, also read or display those stills together in the same turn so Orca presents the batch in its native full-screen still gallery for keyboard or button navigation. Keep `media-gallery` as the review surface and include videos there; Orca's native agent-output gallery currently supports still images, not videos.
- Give me each file's absolute path on the host. In the agent sandbox, keep the repository or worktree under a shared project directory so its `.tmp/` files are available at the same host paths.

## One-off file sharing

- `/mnt/media3/agent-share/` on the media host is available for sharing a one-off file only when I explicitly request it. Copy only the requested files there and preserve the local originals.
- Verify that the destination is on the mounted NFS share before writing. If it is unavailable, report the failure; never create a local fallback under the mount path.
- Use a descriptive, unique filename or task directory, never overwrite a different existing file, and copy with `rsync -a --partial`. After a successful transfer, give me the absolute shared path. Do not automatically archive or delete these shared files.

## Asset storage

- Keep assets actively used by the current task or application on the host. Archive old assets that are no longer actively used to `/mnt/media3/agent/$REPO_NAME/`, including inactive assets in `.tmp/` and other output directories. Use the main repository's name for `REPO_NAME`, not a linked worktree's name; derive it from the parent of `git rev-parse --path-format=absolute --git-common-dir` for a normal or linked checkout.
- Preserve original files and their relative directory structure, separating task or worktree outputs where needed to avoid collisions. Never overwrite a different archived file. Leave a small local index at `.tmp/asset-archive.md` recording original locations and absolute archive paths so future sessions can retrieve them.
- Bundle inactive asset batches into local `.tar.zst` archives using Zstandard level 3 with four threads (`tar -I 'zstd -3 -T4' -cf archive.tar.zst ...`), then copy with `rsync -a --partial`. This is the default balance of compression and CPU work; do not increase the level without evidence that the extra savings justify it. Already compressed media and cooked game archives may shrink little.
- If `zstd` is unavailable, run the creation or extraction command through `nix shell nixpkgs#zstd -c ...`.
- Bundling avoids NFS file creation and metadata overhead for batches of small assets. Preserve original file bytes and relative paths inside the tar; do not transcode images or videos. Use separate archives per task or worktree, or include their distinct paths in a combined archive. Check staging space first and split large batches when necessary. Individual large files can be copied directly with `rsync`.
- Verify that the destination is on the mounted NFS share before writing. Copy with `rsync` and remove local originals only after the transfer succeeds and the sources are confirmed unchanged. Rely on rsync's transfer verification; do not copy archives back, reread them from NFS for checksum verification, or run routine restore tests. If the share is unavailable or a transfer fails, keep the local files and report it; never create a local fallback under the mount path.
- Keep a plain external manifest beside each archive mapping original absolute paths to archive members and each file's SHA-256, plus the staged compressed archive's checksum. The manifest must be readable without decompressing the archive. Record the manifest, archive checksum and extraction root in `.tmp/asset-archive.md`. Confirm the source file set and contents have not changed before removing the transferred originals; retain any changed files. Delete local staging archives after a successful transfer.
- When an archived asset is needed again, copy it back to local working storage before using it and keep the archived copy. Assets referenced by the application, builds or current work remain active; don't move tracked assets or break existing references.
- Retrieve archives only when their assets are needed; consult the external manifest to browse their contents. Copy the archive to local staging and extract into a fresh local directory (`tar --zstd -xf archive.tar.zst -C staging`). Restore the needed paths from there under the recorded extraction root, checking existing files so retrieval does not overwrite newer work. Extract the whole archive when members depend on tar hardlinks. Keep the archive copy on NFS.
